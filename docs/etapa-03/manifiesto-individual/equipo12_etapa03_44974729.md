1. Aporte realizado

En esta etapa trabajé en la creación de las tablas y en la carga de datos para el sistema de la joyería en SQL Server.
Me encargué específicamente de tres tablas: MedioPago, EstadoCompra y Proveedor.
En el script DDL armé la estructura de cada una, definiendo los tipos de datos para los textos, los identificadores numéricos automáticos y las reglas para que no se repitan nombres ni CUITs, además de validar que los correos electrónicos tengan un formato válido.
En el script DML cargué 8 registros de prueba por tabla con datos reales del rubro para verificar que todo funcione y para que mis compañeras tengan datos disponibles al momento de cargar las compras.
También preparé el código para que cree la base de datos si todavía no existe, hice consultas para contar que se hayan insertado las 8 filas por tabla y coordiné con mis compañeras para que las tablas se conecten bien entre sí.

2. Decisiones en las que participé

Participé en las siguientes decisiones del proyecto:
- Usar numeración automática (IDENTITY) en los IDs de MedioPago, EstadoCompra y Proveedor para no tener que cargarlos a mano.
- Definir que no se puedan repetir nombres de medios de pago, nombres de estados ni números de CUIT (usando UNIQUE).
- Agregar una regla para verificar que el mail del proveedor contenga arroba y punto si se decide ingresar uno.
- Definir que MedioPago se relacione con Compra para registrar cómo le paga la joyería al proveedor, teniendo en cuenta que más adelante esa misma tabla servirá para cobrarle a los clientes en las ventas.
- Acordar el orden de trabajo: mis tablas tenían que crearse y cargarse primero para que la tabla Compra pueda usar esos datos sin dar error.

3. Problemas o dificultades identificadas

- Al revisar el diagrama del grupo notamos que la tabla MedioPago había quedado suelta sin conectarse a nada, que a Compra le faltaba la conexión con Proveedor y que había quedado una columna sin definir llamada New Column.
- Había diferencias en la forma de nombrar las cosas entre compañeros; por ejemplo, se había usado codigoProducto en lugar de idProducto.
- Una compañera ya había creado y ejecutado la tabla Compra sin incluir la clave foránea hacia MedioPago, por lo que tuvimos que ver cómo agregar esa columna sin perder lo que ya estaba hecho.
- Al abrir SQL Server aparecían archivos de otra materia en la lista de archivos varios, lo que generaba dudas sobre si se podían mezclar las bases de datos.

4. Soluciones o propuestas realizadas

- Acordamos con el equipo conectar MedioPago y Proveedor directamente a la tabla Compra a través de sus IDs correspondientes, logrando que el modelo quede completo y coherente con las 10 tablas pedidas.
- Unificamos los nombres para que todas las claves primarias empiecen con "id" (como idProducto), actualizando el diagrama para que todos usemos el mismo criterio.
- Para la tabla que ya estaba creada, propuse la opción de usar ALTER TABLE para agregar la columna y la clave foránea sin borrar nada, o bien borrar y volver a crear las tablas en orden para que el script quede limpio.
- Hice consultas con COUNT para verificar rápido en pantalla que se hubieran guardado exactamente los 8 registros en cada una de mis tres tablas.
- Preparamos el reemplazo de la imagen del diagrama relacional en GitHub para que quede subida la versión corregida.
