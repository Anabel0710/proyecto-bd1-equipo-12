## 1. Aporte realizado

Durante esta etapa participé en la implementación física de la base de datos del sistema de gestión comercial y control de inventario para la joyería.

Mi aporte principal consistió en desarrollar las tablas `ROL`, `USUARIO` y `CONSULTA` mediante un script DDL compatible con SQL Server. Para estas tablas definí sus atributos, tipos de datos, claves primarias, claves foráneas y restricciones de integridad.

También preparé el script DML correspondiente, incorporando:

- 8 registros para la tabla `ROL`.
- 10 registros para la tabla `USUARIO`.
- 10 registros para la tabla `CONSULTA`.

Además, fui responsable de organizar y subir estos archivos al repositorio del equipo.

## 2. Decisiones en las que participé

Participé en la definición de los tipos de datos y las restricciones correspondientes a las tablas asignadas.

Propuse que el correo electrónico de cada usuario tuviera una restricción `UNIQUE`, para cumplir con la regla de negocio que impide registrar cuentas duplicadas.

También participé en las siguientes decisiones:

- Utilizar campos `IDENTITY` para generar automáticamente los identificadores.
- Relacionar cada usuario con un rol mediante una clave foránea.
- Aplicar `ON UPDATE CASCADE` y `ON DELETE NO ACTION` en la relación entre `USUARIO` y `ROL`.
- Permitir que una consulta pueda ser enviada por un usuario registrado o por un visitante.
- Utilizar `ON DELETE SET NULL` para conservar las consultas cuando el usuario asociado deja de estar disponible.
- Definir valores permitidos para el estado de una consulta mediante una restricción `CHECK`.
- Establecer el estado `Pendiente` como valor predeterminado.

Estas decisiones fueron revisadas teniendo en cuenta el modelo relacional desarrollado durante la etapa anterior y las necesidades del sistema.

## 3. Problemas o dificultades identificadas

Una de las dificultades encontradas fue determinar el orden correcto de creación e inserción de datos, debido a que las claves foráneas requieren que las tablas y registros referenciados existan previamente.

También fue necesario adaptar la implementación a la sintaxis propia de SQL Server, especialmente en el uso de `IDENTITY`, `NVARCHAR`, `DATETIME2`, restricciones nombradas y reglas de integridad referencial.

Otra dificultad fue representar correctamente las consultas realizadas por visitantes, ya que estos no necesariamente poseen un usuario registrado en el sistema.

## 4. Soluciones o propuestas realizadas

Para resolver las dependencias entre tablas, propuse crear primero la tabla `ROL`, después `USUARIO` y finalmente `CONSULTA`. El mismo criterio fue utilizado para ordenar las inserciones del script DML.

Para contemplar las consultas de visitantes, se permitió que el campo `id_usuario` de la tabla `CONSULTA` admita valores nulos. Al mismo tiempo, se almacenan el nombre y el correo del remitente para identificar a la persona que realizó la consulta.

Realicé pruebas en SQL Server para verificar:

- La creación correcta de las tres tablas.
- La ejecución de las restricciones y relaciones.
- La carga de los registros de prueba.
- La cantidad de registros insertados.
- La recuperación de los datos mediante sentencias `SELECT`.

Finalmente, corregí y ordené el contenido de los scripts antes de dejarlos disponibles en el repositorio.
