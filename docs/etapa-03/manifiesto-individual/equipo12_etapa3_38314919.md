1. Aporte realizado

Durante esta etapa participé en la implementación física de la base de datos del Sistema de Gestión Comercial y Control de Inventario para Joyería utilizando Microsoft SQL Server.

Mi aporte principal consistió en desarrollar el script DDL correspondiente a las tablas "Genero", "Categoria" y "Producto". Definí sus atributos, tipos de datos, claves primarias, restricciones y las claves foráneas que relacionan cada producto con su género y categoría.

También elaboré el script DML para cargar 10 registros de prueba en cada una de las tablas implementadas. Finalmente, documenté el funcionamiento de este módulo y realicé consultas para verificar la creación de las tablas y la correcta inserción de los datos.

2. Decisiones en las que participé

Participé en las siguientes decisiones:

- Utilizar identificadores automáticos mediante "IDENTITY".
- Mantener "Genero" y "Categoria" como tablas independientes para evitar información repetida.
- Incorporar "idGenero" e "idCategoria" como claves foráneas en "Producto".
- Definir restricciones "UNIQUE" para impedir la repetición de nombres de géneros y categorías.
- Utilizar restricciones "CHECK" para evitar precios y cantidades de stock inválidos.
- Limitar el estado de un producto a los valores "ACTIVO" e "INACTIVO".
- Establecer valores predeterminados para el stock actual, el stock mínimo y el estado.
- Utilizar datos coherentes con el dominio de una joyería para probar las tablas implementadas.

Estas decisiones fueron revisadas con el equipo para mantener una nomenclatura y estructura compatibles con los scripts desarrollados por las demás integrantes.

3. Problemas o dificultades identificadas

Una de las dificultades fue establecer correctamente el orden de creación y carga de las tablas, debido a que "Producto" depende de los registros existentes en "Genero" y "Categoria".

También fue necesario revisar los tipos de datos utilizados para los precios y definir restricciones que impidieran registrar valores negativos en los precios o en las cantidades de stock.

Otra dificultad fue mantener una nomenclatura uniforme entre mi módulo y las tablas implementadas por las demás integrantes del equipo.

4. Soluciones o propuestas realizadas

Para respetar la integridad referencial, primero se crearon y cargaron las tablas "Genero" y "Categoria", y posteriormente se creó y pobló la tabla "Producto".

Se incorporaron claves primarias, claves foráneas y restricciones "NOT NULL", "UNIQUE", "DEFAULT" y "CHECK". También se revisaron los nombres de las tablas, atributos y restricciones para mantener el criterio acordado por el grupo.

Para validar la implementación, ejecuté consultas "SELECT" y "COUNT", comprobando que se almacenaran 10 géneros, 10 categorías y 10 productos, y que cada producto quedara relacionado correctamente con su género y categoría.
