## 1. Aporte realizado


Durante esta etapa participé en el desarrollo de consultas SQL para responder a necesidades de información del Sistema de Gestión Comercial y Control de Inventario para Joyería, utilizando Microsoft SQL Server.

Mi aporte principal consistió en desarrollar la Consulta de Negocio Avanzada con Filtro Post-Agregación, cuyo objetivo es identificar a los vendedores activos que alcanzaron o superaron un monto de facturación de $100.000, para facilitar el análisis de objetivos comerciales y la evaluación de posibles comisiones o premios.

Para realizar esta consulta combiné cuatro tablas: "Usuario", "Rol", "Comprobante" y "DetalleComprobante", mediante la cláusula "INNER JOIN". De esta manera, la consulta relaciona los datos de los empleados con sus roles y con las operaciones de venta registradas, incluyendo el detalle de los productos vendidos.

También incorporé condiciones mediante "WHERE" para seleccionar únicamente a los usuarios activos que poseen el rol de vendedor. Posteriormente, utilicé "GROUP BY" para agrupar las operaciones por vendedor y calcular los indicadores correspondientes.

La consulta calcula la cantidad de comprobantes asociados a cada vendedor mediante "COUNT(DISTINCT c.idComprobante)" y el importe total facturado mediante "SUM(dc.Cantidad * dc.PrecioUnitario)". Finalmente, apliqué "HAVING" para mostrar exclusivamente a los vendedores cuyo total facturado sea igual o superior a $100.000 y utilicé "ORDER BY" para ordenar los resultados de mayor a menor facturación.

## 2. Decisiones en las que participé

Para desarrollar la consulta avanzada, tomé las siguientes decisiones de implementación:

- Aplicar condiciones con "WHERE" para limitar los resultados a los usuarios cuyo rol sea "'Vendedor'" y cuyo estado sea "'Activo'".
- Utilizar "GROUP BY" para consolidar los datos de las ventas por vendedor.
- Calcular el total facturado mediante la suma de la cantidad de unidades vendidas multiplicada por su precio unitario.
- Utilizar "COUNT(DISTINCT c.idComprobante)" para contar los comprobantes diferentes asociados a cada vendedor sin contar varias veces un mismo comprobante cuando contiene distintos renglones de detalle.
- Aplicar "HAVING" con el umbral de $100.000 para filtrar los grupos según el total de facturación calculado.
- Ordenar los resultados de forma descendente mediante "ORDER BY TotalFacturado DESC", para presentar primero a los vendedores con mayor facturación.

## 3. Problemas o dificultades identificadas

Una de las principales dificultades conceptuales de esta consulta consiste en distinguir entre los filtros aplicados a los registros individuales y los filtros aplicados a los resultados de una agregación.

La condición relacionada con el estado del usuario y su rol puede aplicarse mediante "WHERE", porque se evalúa sobre los registros antes de realizar el agrupamiento. En cambio, el objetivo mínimo de facturación depende de la suma de las ventas de cada vendedor, por lo que debe evaluarse después de agrupar los registros.

Otra cuestión importante es evitar el conteo duplicado de comprobantes. Como una venta puede contener varios productos y, por lo tanto, varios registros en "DetalleComprobante", contar directamente las filas resultantes de los "JOIN" podría producir una cantidad de comprobantes incorrecta. Para resolver esta situación se utilizó "COUNT(DISTINCT c.idComprobante)".

Además, la consulta depende de que los nombres de las tablas, los atributos y las relaciones coincidan con la estructura real de la base de datos implementada en las etapas anteriores.

## 4. Soluciones o propuestas realizadas

Para resolver la necesidad de información planteada, desarrollé una consulta que integra operaciones de combinación, filtrado, agrupamiento y agregación.

La utilización de "INNER JOIN" permite recuperar únicamente los registros que tienen correspondencia entre las tablas relacionadas. El uso de "WHERE" limita el análisis a los vendedores activos, mientras que "GROUP BY" permite consolidar las operaciones correspondientes a cada uno.

Para calcular los indicadores comerciales, incorporé las funciones de agregación "SUM" y "COUNT". La primera permite obtener el importe total facturado por vendedor, mientras que la segunda, combinada con "DISTINCT", permite contar los comprobantes diferentes asociados a cada uno.

La solución principal consiste en aplicar la condición "HAVING SUM(dc.Cantidad * dc.PrecioUnitario) >= 100000.00", que permite seleccionar únicamente a los vendedores que alcanzaron el objetivo establecido.

Finalmente, incorporé "ORDER BY TotalFacturado DESC" para facilitar la lectura y comparación de los resultados.

La consulta fue planteada para ejecutarse en Microsoft SQL Server, utilizando la base de datos "BD_Joyeria_Practica". La validación definitiva requiere comprobar su ejecución con la estructura y los datos disponibles en el proyecto.
