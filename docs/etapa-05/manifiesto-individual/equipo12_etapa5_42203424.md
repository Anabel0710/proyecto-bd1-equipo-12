1. Aporte realizado

Durante esta etapa participé en el desarrollo del tema de Triggers de Auditoría para el proyecto "Sistema de Gestión Comercial y Control de Inventario para Joyería".

Mi trabajo consistió en diseñar una implementación de triggers en SQL Server para mejorar la trazabilidad y el control de las operaciones realizadas sobre la base de datos.

Se propuso la creación de una tabla auxiliar denominada "AuditoriaProducto", destinada a conservar un historial de las modificaciones y eliminaciones realizadas sobre los productos.

También desarrollé dos triggers:

- "tr_AuditarProducto": registra automáticamente las operaciones "UPDATE" y "DELETE" realizadas sobre la tabla "Producto", almacenando el código del producto, los valores anteriores y nuevos del precio y stock, el tipo de operación, la fecha y el usuario de SQL Server.
- "tr_BloquearEliminacionCompra": impide la eliminación de registros de la tabla "Compra", mostrando un mensaje para proteger el historial de adquisiciones.

Además, preparé las pruebas SQL necesarias para comprobar el registro de las operaciones y el bloqueo de eliminaciones.

2. Decisiones en las que participé

Participé en la elección de la tabla "Producto" para implementar la auditoría, debido a que contiene información importante para el control del inventario, como el precio de venta y el stock disponible.

También se decidió utilizar una única tabla auxiliar para almacenar los eventos de actualización y eliminación, diferenciándolos mediante el campo "TipoOperacion".

Para el bloqueo de eliminaciones se seleccionó la tabla "Compra", considerando la importancia de conservar el historial de adquisiciones realizadas a proveedores.

Por último, se decidió utilizar las tablas lógicas "inserted" y "deleted" de SQL Server para recuperar los valores involucrados en cada operación.

3. Problemas o dificultades identificadas

Una de las principales dificultades fue comprender cómo funcionan los triggers en SQL Server y cómo diferenciar las operaciones "UPDATE" y "DELETE" utilizando las tablas especiales "inserted" y "deleted".

También fue necesario analizar cómo adaptar la implementación al modelo relacional del proyecto, respetando los nombres y tipos de datos definidos en las tablas existentes.

Otra dificultad fue distinguir entre los triggers destinados a auditar operaciones y aquellos utilizados para impedir determinadas acciones, ya que ambos cumplen objetivos diferentes.

4. Soluciones o propuestas realizadas

Para resolver estas dificultades, se propuso centralizar la auditoría de modificaciones y eliminaciones de productos en un único trigger, diferenciando las operaciones mediante la información disponible en "inserted" y "deleted".

Se diseñó la tabla "AuditoriaProducto" para conservar los valores anteriores y nuevos, junto con la fecha, el usuario y el tipo de operación.

Además, se implementó la propuesta de un segundo trigger de tipo "INSTEAD OF DELETE" sobre "Compra", con el objetivo de interceptar los intentos de eliminación y evitar que se pierda información del historial comercial.

Finalmente, se prepararon pruebas para verificar el comportamiento de ambos mecanismos.
