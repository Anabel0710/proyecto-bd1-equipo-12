1. Aporte realizado
Durante esta etapa participé en el desarrollo del tema de Procedimientos y Funciones Almacenadas para el proyecto (BD_JoyeriaAlba).

Mi trabajo consistió en diseñar e implementar rutinas programables en SQL Server Express para centralizar la lógica comercial, automatizar el flujo transaccional de ventas y optimizar las consultas del catálogo de productos y clientes.

Desarrollé tres componentes de programabilidad en T-SQL:

dbo.fn_CalcularDescuentoCliente: Función escalar encargada de evaluar el historial acumulado de compras realizadas por un cliente para determinar el porcentaje de descuento a aplicar (0%, 5% o 10%).

dbo.fn_ObtenerProductosPorCategoria: Función de tabla alineada que retorna el catálogo de joyas y relojes disponibles en stock filtrados por una categoría específica.

dbo.sp_RegistrarVentaCompleta: Procedimiento almacenado que ejecuta en una única operación atómica el flujo de venta completo: validación de stock, cálculo automático de descuento, inserción de la cabecera del comprobante, registro del renglón en el detalle y la actualización inmediata del inventario en la tabla Producto.

Además, preparé las pruebas SQL y las capturas de pantalla de ejecución en SQL Server Management Studio para comprobar el correcto funcionamiento de cada objeto.

2. Decisiones en las que participé
Participé en la definición del esquema de descuentos acumulados por fidelidad, decidiendo utilizar la tabla DetalleComprobante para calcular el monto total gastado históricamente por cada cliente antes de aplicar un beneficio.

Se decidió implementar dbo.fn_ObtenerProductosPorCategoria como una función de tabla alineada (inline table-valued function) para simplificar las consultas desde el sistema cliente, evitando la repetición de instrucciones JOIN complejas entre las tablas Producto, Categoria y Genero.

Para el registro de ventas, se optó por consolidar la lógica dentro del procedimiento almacenado dbo.sp_RegistrarVentaCompleta, utilizando un parámetro de salida (OUTPUT) para recuperar el ID del comprobante recién generado mediante SCOPE_IDENTITY().

Por último, se decidió delegar en el procedimiento almacenado el descuento directo sobre el campo StockActual de la tabla Producto, garantizando que no existan inconsistencias ni despasajes en el inventario durante las transacciones.

3. Problemas o dificultades identificadas
Una de las principales dificultades fue comprender las diferencias conceptuales entre una función escalar y un procedimiento almacenado en SQL Server, especialmente respecto a las operaciones DML permitidas (INSERT, UPDATE, DELETE) y el tipo de valores que retorna cada objeto.

También fue necesario analizar la integración de las funciones dentro de la lógica del procedimiento almacenado, asegurando que los tipos de datos decimales y los porcentajes de descuento se calcularan e insertaran correctamente en la tabla DetalleComprobante.

4. Soluciones o propuestas realizadas
Para resolver estas dificultades, propuse estructurar las reglas de cálculo en una función escalar independiente (dbo.fn_CalcularDescuentoCliente), permitiendo su reutilización tanto en consultas SELECT directas como dentro del procedimiento almacenado de ventas.

Se diseñó el procedimiento dbo.sp_RegistrarVentaCompleta agregando comprobaciones previas mediante RAISERROR para verificar la existencia del producto y asegurar que el stock actual cubra la cantidad solicitada antes de realizar cualquier modificación en las tablas.

Asimismo, propuse centralizar la ejecución de pruebas mediante scripts de demostración que validaran secuencialmente la función escalar, la función de tabla y el procedimiento almacenado, verificando el estado del inventario antes y después de cada prueba.

Finalmente, organice las capturas de evidencia e integré la documentación en formato Markdown (docs/etapa-05/procedimientos-funciones.md) enlazando las imágenes almacenadas en el repositorio.
